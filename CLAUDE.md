# CLAUDE.md — made by aryan

Personal project on personal infra only: public npm (`.npmrc`), personal GitHub (At0m0verr1de), Cloudflare Workers static assets, Supabase.
- Live at https://rups.fun (Workers custom domain in `wrangler.jsonc`). The old workers.dev address and www.rups.fun are redirected in the browser by an inline script in `src/shared/Layout.astro`, because static assets are served before the Worker runs. Sign-in on preview URLs needs `https://*-madebyaryan.aryanbakshi2021.workers.dev/**` in Supabase Redirect URLs.
Never point it at work registries, work GitHub orgs, or work services.

## Build & Test
- `npm run build` — static build to `dist/`
- `npm test` — Node test runner over `src/**/*.test.js`
- `supabase/tests/run.sh` — applies every migration to a throwaway Postgres DB and runs RLS checks (expects container `pg-wordle-test`)
- Devpod preview: `devpod serve dist-preview`, then `scripts/preview-devpod.sh /proxy/<devpod>/<port>/`
- Run npm/astro from the repo root. Running astro from another cwd writes a stray `.astro/` there.

## Architecture
- One toy = `src/toys/<slug>/` (meta.ts + code) + `src/pages/<slug>.astro`. Homepage globs `src/toys/*/meta.ts`.
- Links must use `import.meta.env.BASE_URL` (the devpod preview is served under a sub-path).
- Toy pages that render with innerHTML need `<style is:global>`; scoped styles don't reach generated markup.
- Supabase: toy tables live in `public` as `<toy>_*` (no per-toy exposed-schema config). Shared: `counters`, `scores`.

## Key Invariants
- RLS on every table. Cross-row checks go through `security definer` helpers to avoid policy recursion.
- Grant column-level `update` only on user-editable columns.
- Supabase auto-grants ALL on new public objects; `20261009000200_tighten_grants.sql` disables that, so every toy migration must grant exactly what it uses.
- The test stub mirrors Supabase's default grants, so a missing revoke shows up as a FAIL locally.
- Project is in Tokyo; DB access goes through `aws-0-ap-northeast-1.pooler.supabase.com` (direct host is IPv6-only).
- Wordle Duo no-spoiler rule is enforced in SQL (`"no spoilers"` policy), never only in the client.
- Every player signs in with Google (`src/shared/supabase.js`); anonymous sign-ins stay off. The anon key is public; the service_role key never enters this repo.
- OAuth returns to `location.href`, so every deploy/preview origin must be listed in Supabase → Authentication → URL Configuration → Redirect URLs.
- Add a case to `supabase/tests/wordle_rls_test.sql` for every new policy.
- `.env.production` is committed and holds only browser-safe values; secrets never go there.
- Commits here must stay unsigned and use the At0m0verr1de identity (repo-local git config overrides the devpod's signing and hooks).
- Telemetry: `track()` / `reportError()` from `src/shared/telemetry.js` → `/api/events` → `worker/index.js` → Workers Logs (free: 200k events/day, ~3-day retention). New event names must be added to `EVENTS` in `worker/index.js` or they are dropped. Never log names, emails, or player-typed text.
- `worker/index.js` only runs for paths with no static file; static pages never invoke it. Invocation logs are off to save log quota.
- Wordle Duo screenshot reading (all in the browser): `parse.js` (tile colours + boxes) → `/api/wordle/<date>` (worker proxies NYT's answer, edge-cached; dates after tomorrow refused) → `ocr.js` letter scores → `solve.js` `verifyBoard` (blocks other days' boards) + `decodeBoard` (words that fit the colours) → player confirms words. `parse.js` rejects a board unless filled rows + empty outlined rows below = 6, so a crop can't hide earlier guesses. `verified` is set by the client, so it's a hint, not proof. Colours + answer do most of the work; OCR only ranks candidate words. `words.js` (~74 KB) must stay a dynamic import. OCR accuracy is guarded by `ocr.test.js` (draws boards with @napi-rs/canvas).
- Partner mode (`src/shared/space.js`): a couple is a 2-person Wordle room with `kind = 'couple'` (one per person, enforced in SQL RPCs). With a couple, `/` is the couple home and Wordle opens the couple room directly; the hidden "Mode" switch in the profile menu flips to general mode ("Groups"), which never lists or opens the couple room: partner and groups are separate spaces. `data-mode="couple"` on `<html>` drives the blush theme in `theme.css`.
- Groups (`wordle_rooms` with `kind = 'group'`, up to 10, an `icon`; the table names are historical, rooms are site-wide): the header's switcher (`src/shared/group-switch.js`) picks `space.group` from any page and fires `GROUP_EVENT`; pages that redraw in place set `data-groups="live"` on `<html>` and listen, other pages navigate to the leaderboard. Wordle in a group is "Wordle Leaderboard" (`leaderboard.js`: day ranks by guesses, standings by points 6..1, X = 0). Only the creator removes people (`wordle_remove_member`); a leaving creator hands over, an empty room is deleted (trigger). One page, two routes (`WordlePage.astro`): couples live at `/wordle-duo/`, groups at `/wordle-leaderboard/` (`groupSlug` in meta); the app rewrites the address to match the open room, and invite links follow the room kind. Either route accepts `?join=CODE` for either kind, so old links still work.
- Wordle results belong to the person (`wordle_results` pk `(user_id, puzzle_no)`, no room column): one upload counts in the couple room and every group. Visible to anyone sharing a room with you, once they've played that puzzle (`wordle_shares_room` + `wordle_has_played`).
- Drinks (`src/toys/drinks/`, `couple: true` in meta = only on the couple home): everything is counted in shots, 1 shot = 30 ml at 40% = 12 ml alcohol (`shotsOf` in stats.js). Drinks before 6am count for the previous night. The jug is a fixed 15 shots a month (180 in year view, `jugOf`); over it you're "cut off". RLS: you read your own rows and your partner's (`is_partner()`), and write only your own. PostgREST upserts rewrite conflict keys, so tables that get upserted need update on those key columns too.
- Chess Mates (`src/toys/chess-mates/`, couple-only): the **database** fetches chess.com, not the browser or the Worker. `chess_get` wraps the `http` extension (3s timeout, User-Agent with contact email, ETag/If-None-Match); requests are strictly serial (chess.com 429s parallel ones). `chess_names`/`chess_sync`/`chess_games` have RLS on and no grants; the page only calls `chess_state`, `chess_set_names`, `chess_sync`. `chess_sync` is throttled to 60s (chess.com's archive cache is max-age=60) except while `backlog` (older months both played, newest first) is non-empty, 3 months per call; pg_cron `chess-sync` runs `chess_sync_all()` at `23 */3 * * *`, 6 requests per room. Changing a username wipes that room's games. Only games between the two usernames with `rules='chess'` are kept. chess.com policy: no chess.com branding/board colours/piece art (we use unicode pieces on our own blush board), no engine analysis (accuracy shown is chess.com's own review). The `http` extension's functions are owned by supabase_admin so PUBLIC execute can't be revoked; it's safe only because the `extensions` schema isn't exposed by PostgREST.
- Kitne Ka? (`src/toys/kitne-ka/`, couple-only): daily price-guessing. `price_items` (seeded by `*_kitne_items.sql`, every price sourced with `source` + `as_of`) and `price_guesses` have RLS on and no grants; the page calls only `price_today()` and `price_guess(slot, rupees)`. The day is the India date; the day's five walk a fixed md5 shuffle of active items five at a time (`price_items_for`), so adding items reshuffles future days only. An item's price, and your partner's guess for it, come back only after you've guessed it; your partner's day total only once you've done all five. Points: `100 × (1 − |ln(guess/price)| / ln 3)`, same formula in price.js for display. To add or fix prices: a new migration with inserts/updates (update `as_of` too).
- Our Little Pet (`src/toys/our-pet/`, couple-only): `pets` stores meters as of `updated_at`; `pet_now()` works out the live values lazily (hunger 0 in 48h, happiness 0 in 72h, health slow base rate plus extra per empty meter, tuned so a full pet left alone dies at exactly 7 days). Nothing runs on a schedule. `pet_act('feed'|'play'|'pet')` has per-person daily allowances (3/6/12) and does nothing past them or once dead; triggers on wordle_results, drinks, jar_slips, chess_games and price_guesses call `pet_boost` once per toy per person per India day (wrapped so it can never fail the original insert). `pet_adopt` needs both partners and moves a dead pet to `pet_graves`. Mood and every line the pet says are client-side in pet.js (nudges about unplayed toys, never about drinking). Tables are RLS-on, no grants; only `pet_state`, `pet_adopt`, `pet_act` are callable. The pet is a cat; `pets.colour` holds the coat key (`COATS` in pet.js: black/grey/ginger/cream/white/tuxedo, the egg you pick decides it), so a new coat needs a migration for `pets_colour_check`. The page is a full-bleed SVG room (`room.js`, 1600×900 world units, art bleeds past the edges and down to y 1500 so the JS camera can widen or slide the viewBox clear of the dock/panels). `cat.js` is a procedural rig (poses lerped, IK legs); coat colours are CSS vars on the `<svg>` because the gradients live in the room's `<defs>`. In app.js one activity runs at a time (`startActivity` bumps a token; loops check `alive(token)`); food, ball and feather catches only count when the server applies `pet_act`. Time of day comes from IST (`?time=` overrides).
- Date Jar (`src/toys/date-jar/`, couple-only): `jar_slips` + `jar_vetoes` have RLS on and no grants at all; every read and write is a security-definer RPC (`jar_state`, `jar_add`, `jar_remove`, `jar_draw`, `jar_veto`, `jar_done`) scoped to `jar_room()` = your couple room. `jar_state` blanks the idea of partner slips still in the jar (cost/place/length stay as a teaser). The draw is server-side `order by random()`, so both phones get the same slip; a partial unique index allows one drawn slip per room; one veto per person per rolling 7 days. Money: a slip's `cost` is the whole date, `payer` null = split 50/50 (`shareOf` in jar.js). The page animates a partner's draw when a realtime ping shows a slip went jar → drawn.
- Invite-only: `site_has_access()` = on the `site_access` allowlist (SQL editor only) or a member of any room. Joining by invite code is always allowed; creating rooms needs access. `/` shows the door to signed-out visitors and "invite only" to signed-in strangers, with a "Request access" button (`request_access()` → `access_requests`, no grants; inserting into `site_access` clears the request via trigger). Approve in the SQL editor: `insert into public.site_access select user_id from public.access_requests r join auth.users u on u.id = r.user_id where u.email = '…';` Static pages are public files, so nothing personal goes in the build; privacy is the DB rules.
- Avatars are emojis (`wordle_members.emoji`); Google photos are never shown or stored.
- Words are never logged in telemetry (they'd spoil the day); only counts/ratios.
- Design iteration: preview on the devpod first (`scripts/preview-devpod.sh`); push a non-main branch for a Cloudflare preview URL when Google sign-in must work; merge to `main` only when final.
